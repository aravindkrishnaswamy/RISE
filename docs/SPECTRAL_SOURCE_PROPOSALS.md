# Spectral source proposal domains

This implements an engine preparation capability, not a production raw-band renderer. It does not certify calibrated emission, complete material coverage, or compatibility with every integrator. No existing rasterizer silently enables this mode.

## Preparation and sampling

`SpectralSourceDomain::Create(nodes, uniformSourceMass=.05, revision=1)` creates immutable quadrature configuration. Each `Node` has ordered positive finite `nm` and positive finite `weight`; a single `{1200,1}` is a fixed-wavelength proposal estimate. These weights do not define the transport wavelength PDF or claim measured source coverage. Multi-lane transport must supply a domain covering every active lane. The revision is caller metadata; domain replacement through the caster setter always rebuilds even for an identical pointer/revision, avoiding an incomplete equality/cache key.

`RayCaster::SetSpectralSourceDomain(shared_ptr<const SpectralSourceDomain>)` is a concrete preparation seam. Set it before scene attachment, or call it while idle to rebuild the current attachment. `nullptr` selects legacy preparation. No IJob/ILight/ICamera vtable or parser change is introduced. The caster retains the scene; its LightSampler owns per-pass proposal tables and retains the domain, while EnvironmentSampler and LightSampler retain the actual environment map. Frozen scene/assets must remain immutable during sampling. Source/geometry/time changes require `RefreshLightSamplers`, explicit invalidation plus AttachScene, or a domain replacement before rendering; ordinary scene-generation AttachScene invalidation continues to work. Two simultaneous casters can prepare distinct tables over one unchanged scene.

Finite positional light weights use actual `emittedRadianceNM` over the domain plus deterministic sphere angular quadrature; meshes use deterministic surface/domain `radiantExitanceAtNM` with world/object/UV/normal/camera/ObjectInfo records and optional signal probing, area and emitting-face count. These estimates are approximate, including angular quadrature for narrow spots. No estimate is a blackness certificate. Tagged log masses avoid overflow of power products/sums; normalized PMFs include a positive uniform-source mixture, including all-zero estimates. No domain cache is written onto shared lights, emitters, painters or maps.

Spectral preparation evaluates the actual environment map. A nonnegative caster `SetRadianceScale` override must match that map’s scale; the normal Job wrapper updates both. A mismatched or nonfinite override fails preparation explicitly, including attempts to recover a nonzero source from a zero-scale map. Clearing the override or updating both values allows a retry.

The first environment baseline is deliberately uniform WORLD-SPHERE only: Sample/Pdf = 1/(4*pi) everywhere. It is not a spectral directional CDF or an optimized band proposal. Root-class power is an approximate equal-solid-angle integral of actual `IRadianceMap::GetRadianceNM` queries, preserving map scale/orientation/current time adapters. A missed patch retains complete directional support. Root class selection mixes the estimated finite total and environment sphere-integral times scene-disc area with a positive uniform two-class mass. Three densities remain separate: finite PT NEE alias q; independent PT environment directional q; and root selection `(1-envShare)*finite_q` / `envShare`. Tests assert these separately.

BVH, RIS and light-sample RR are forcibly disabled by domain-aware setters and every Prepare, including Prepare's >8-source auto-RIS and caster pending-setting/rebuild/refresh paths. Legacy no-domain configured behavior is unchanged. Directional/ambient direct evaluation stays deterministic; admitted positional sources never enter that arm based on RGB blackness.

## Adjacent correctness bug found and fixed

The preexisting NM direct-light estimator accumulated deterministic directional/ambient emission, then overwrote it in both selected point and selected mesh branches. Both assignments now add, matching the RGB implementation. The focused test covers directional+point and directional+area. Pel already added; HWSS direct lighting delegates to `EvaluateDirectLightingNM` (PathTracingIntegrator.cpp generic NM dispatch and explicit HWSS lane loop), so it receives this fix without a third implementation. Root emission has no deterministic direct-light accumulator and is inapplicable. The spy test separately proves a RGB-black point did not enter the deterministic arm: a one-point energy oracle alone would be false-green because that old overwrite hid a duplicate call.

## Scope and required production follow-up

This seam is not enabled by any existing rasterizer and does not establish raw radiometric output or full-integrator compatibility. Raw source/material/sky coverage/provenance preflight is NOT implemented here. Positive proposal support does not certify calibration: RGB uplift, endpoint-held legacy functions and visible-only analytic skies require explicit rejection/replacement for unsupported bands. No BDPT/VCM/MLT, SMS, guiding, participating-media/fire/equiangular or production HWSS support claim is made. A future raw rasterizer must reject those consumers/features until validated or integrated, install the domain deliberately, and provide P6b film/output without CIE/XYZ normalization/display transforms/OIDN. No current automatic route grants these capabilities.

A tiny one-bounce NM environment oracle exercises actual EvaluateDirectLightingNM plus its environment Pdf query for continuation MIS, with known Lambertian angular integral. A three-node domain is evaluated at independent NM controls; this is not execution of the full HWSS integrator. The remaining full PT NM/HWSS scene/control gates and raw-coverage refusal tests belong to the production attachment phase.

## Numerical support and failed preparation

Arbitrary tiny mixture values can round an environment-dominated root class to exactly one, deleting the finite class through `1-envShare`. The supported proposal policy uses the renderer's 32-bit Sobol grid, not a physical epsilon: require `alpha/N >= 2^-31` (two cells of width `2^-32`) for every finite source table. Domain creation also requires `alpha/2 >= 2^-31` for the binary root classes; actual source-count validation happens during probability construction. With default alpha=.05, the supported count is at most floor(.05*2^31) sources. This keeps each fallback alias interval wider than a Sobol cell even after endpoint rounding and leaves both root complements representable. Unsupported mixture/count combinations fail explicitly. Boundary tests exercise the first, bin-boundary and last legal Sobol values, both root-dominance cases, and rejected tiny mixtures/counts. The reported PDFs remain the continuous proposal densities; the usual finite RNG discretization is not relabeled as exact continuous frequencies.

Source validation can throw. Environment temporaries release through RAII; a caster builds its new LightSampler/LuminaryManager fully under RAII and publishes both only after finite and environment preparation succeed. Domain refresh carries over the previous motion sweep only for the same scene attachment. Because the source scene may already have been mutated, any preparation exception clears the old caster samplers, retains the requested scene/domain/settings, marks a retry required and rethrows. `GetLightSampler()==nullptr` exposes this unprepared state; callers must not render until successful AttachScene/Refresh. Refresh retries even from that empty state. Direct LightSampler::Prepare failures also clear all proposal tables, borrowed prepared pointers, environment refs and prepared flags before rethrowing. Tests inject negative/nonfinite maps, fail after a positional entry while constructing mesh weights, assert refcounts/empty sample and PDF behavior, and prove successful retry.

Tests force a missed mesh-patch root beside a bright competitor and recover its positive actual NM radiance. Uniform environment tests now check sampled world-coordinate moments, cap frequency and deterministic mapping endpoints independently of the reported constant PDF.

Mixed spectral roots additionally draw a fresh conditional uniform value after the environment-versus-finite class roll. Reusing and stretching the class interval would restrict conditional sampling to the few Sobol cells in a rare class, potentially missing finite aliases or environment directions even when each standalone table passed its floor policy. The extra dimension applies only to spectral-domain mixed roots; legacy no-domain and one-class layouts stay unchanged. This avoids a joint-product minimum-probability restriction. A three-finite-source plus overwhelmingly bright environment fixture forces a legal 32-bit class/conditional pair that reaches a missed source; the prior single-roll remapping selected the bright source instead. Production fixed-budget light-root consumers remain excluded pending their own dimensional-budget integration tests.
