# r248 actual native context cold/warm observation

This incremental qualification enters the existing ordinary transport, production
transport and single-stage FCT context factories in a fresh process. The first
production factory call initializes both transport statics. The FCT factory is
separate. Cold means first process-local factory construction; driver/compiler
caches are not cleared or bounded. Constructor-entry atomics count attempts, including failed attempts;
they are neither successful creation counts nor allocation/lifetime counters.
Warm reuse observes unchanged attempt counters. Default numerical dispatch and
canonical serialization are unchanged; exact observer-off/on state and golden
parity remain unqualified.

The qualification collects actual sequential current RSS, physical footprint,
process peak RSS and device allocated bytes before and after factory calls. Metal
device discovery precedes the first sample and can allocate driver resources.
Host and device measurements are independent; their sum is not unique physical
memory. A valid empty source object is used only to reach the existing telemetry
capture; its source layout is unavailable and no source admission is claimed.
The separate fixture policy is 2GiB with 32MiB reserve, not the source campaign
policy. A two-byte ceiling with one-byte reserve refuses before factory entry.
An invalid selector refuses before capture. All controls are standalone, without
an owner, simulation fields, numerical commands, new observer buffers or a run.

The actual contexts expose 43 pipeline reference slots for each transport kind
and 11 for FCT. These are reference slots, not unique allocation identities or
live-byte totals. Each queried pipeline has a positive thread limit, and its
static threadgroup allocation is checked against the queried device limit. Static
threadgroup bytes do not bound registers, spills or compiler/driver scratch.
Successful rows bind a nonzero common actual device registry ID. Constructor
failure, missing telemetry, invalid device/pipeline limits, fixture memory limits
or report publication failure cannot produce a successful validation receipt.
Partial runtime output and failed logs must be retained.

The verifier refuses optimized Python before any file creation or native work;
a separate `-O` RED checks this prerequisite. It requires the exact five-row sequence: telemetry-only, pre-factory
memory refusal, cold creation, warm reuse, invalid selector. It independently
checks counters, actual pipeline reference counts, availability and queried
limits. A separate closed-for-writing stdout control proves publication failure
cannot pass the harness. Strict and changed-native-translation-unit ASan/UBSan
executables run sequentially. Other linked dependencies retain their prior
instrumentation; this is not a whole-library sanitizer claim. Exact source,
archive, object, executable, toolchain and log identities are pinned. Dirty build
identity remains distinct from the original failed producer.

This is actual context observation and a pre-factory refusal prerequisite. It is
not complete native or caller admission. Libraries, functions, strings, transient
compiler allocations and retained driver resources have no measured individual
live ledger here. Projection, force, lazy Merkle, owner setup, stages, commands,
aliases, releases and publication remain to be inventoried; all other already-live
caller families and capacities also remain. Existing Run/device checks and all
campaign/public caps are preserved. Complete reviewed resource admission remains
mandatory before any new observer buffer, actual private hook integration or
full simulation.

Initial R1 identified the optimized-interpreter assertion bypass; the initial
records remain separate. The repaired gate records Xcode destination-selection
notices separately from lowercase compiler/link/AppIntents warnings. Those
orchestration notices preserve the actual selected arm64 destination in full logs.
