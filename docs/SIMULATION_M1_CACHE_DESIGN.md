# M1 cache design

The owner authorized implementation after independent review and M0 acceptance. M1 delivers grid storage and playback. Solver and host implementation belongs to M2. The design and tests below specify proposed behavior.

## Reader and time

A cache reader acquires an immutable snapshot naming one epoch and manifest digest. It exposes output descriptors, declared time support, committed coverage, and lookup by output and frame. One acquire covers all outputs and shutter lookups for a render. Returned frames own their immutable buffers. Retain immutable payloads across rebakes in M1, including those referenced by old snapshots. A live publisher must copy or transfer ownership before reusing a simulation buffer. Test with a non-grid mesh stub, two channels and a reader holding A while the writer publishes B.

Map scene time against the **full authored support** first, then test for a committed entry. Actual sample times stay available as metadata. The legacy adapter delegates mapping to FireSequenceManifest::MapSceneTime, preserving first index, affine scale/origins, floor selection, held flag, half-open error support, exact last endpoint, base time and advection offset. Native partial manifests must declare the intended span even when empty. The old r275 working manifest describes only its current prefix; preserve its existing interpretation on legacy playback and require an independent declared span before adapting it as a growing native bake. General loop/retiming controls belong to M4.

An uncommitted interior slot, including a hole or the first slot, returns unavailable. A preview fire consumer creates its medium from declared extents and physical records, installs a transparent empty frame with an unavailable status and warning, and can refresh next frame. A listed file missing or failing validation returns corruption and refuses that render. Predictive requests reject incomplete manifests and failures during preflight. Validate the frame, medium fields, majorant and emission CDF as a single transaction before render freeze. A refusal retains the old prepared state and denies authorization for the requested render. Empty preview provenance must explicitly describe the unavailable ordinal and coverage, never claim a fabricated source-file digest. Version that outcome separately from existing successfully prepared provenance records.

## Format and bounds

Use a versioned canonical RISECBOR64 manifest: solver/producer version, key, epoch, authored time law, ordered index entries (ordinal, actual time, output, byte size, SHA-256), named typed channels with units, physical records, fidelity and evidence references, completion seal. Give payload types independent identifiers/versions, including reserved mesh, particle and transform families. Unknown type is an explicit unsupported result. Parse known optional extensions only under the format's version rules.

For native grid v1, define an explicit little-endian header and fixed-width lengths/coordinates, IEEE binary32 component bit strings, xyz component order, x-fastest cell order and channel-local signed index origin. Specify transform as binary64 row-major index-to-world affine matrix multiplying column coordinates; state whether integer coordinates refer to sample centers. Preserve the source transform and verify against known index/world point pairs, including translation and nonsymmetric linear terms. Carry background, active mask and stored inactive values separately. Sort channels by canonical name bytes and nonoverlapping blocks by integer origin in a documented lexicographic order. Encode constant tiles without expanding them. Dense regions and sparse blocks decode to one logical view. Reject duplicate names/blocks, overlaps, invalid transform or extent, out-of-range coordinates, truncation, trailing bytes and unsupported versions. Before implementation, pin magic, widths, field order, padding, axis conventions and a hand-encoded golden fixture together in the codec specification/test.

Check lengths and their products before allocating, including sparse-to-dense expansion, descriptors, all simultaneously retained data, validated input snapshot, decoder scratch, preparation and the previously installed frame. Enforce a caller-provided, process-budgeted allocation limit under the 32 GiB ceiling. Bound manifest/CBOR depth, counts and lengths before allocating or recursing. Read from a bounded immutable copy (or private immutable spool), hash it and decode the identical bytes. Never reopen a mutable path between verification and decoding. The VDB importer applies bounds before materializing untrusted grids, including decompression. Use isolated resource-limited import or reject an input whose peak cannot be bounded. Failing a limit must leave the previously readable generation intact.

## Publication, recovery and stale data

One OS-owned exclusive writer lock per logical cache serializes all writers, including new bakes and resumed workers. Publish immutable payloads, sync each file and containing directory, write and sync a temporary manifest, atomically replace the current pointer/generation on the same filesystem, and sync the pointer directory. Choose platform primitives with equivalent durable-replace semantics, or report unsupported publication. Under the lock, verify expected epoch and parent digest before append. Resume only a verified identical prefix and matching key. Repeated index/output and identical content/metadata is idempotent; conflicting data is refused. Seal as a final generation of the same epoch covering the full declared output set; seal and index become visible together. A rebake starts a new epoch. Unpublished temporary files never enter the reader's index. Report writing, interrupted, and complete using lock ownership and durable generation, not elapsed time. A missing cache with a writer but no first generation is baking with zero committed coverage.

Key by canonical effective solver parameters (including effective option overrides), solver id/version and named ordered input hashes. Include backend/build or arithmetic policy when it changes output. Preserve the producing key separately from current scene expectations. Staleness is orthogonal to availability/completion. Stale preview can play with status. A predictive consumer requires matching requested inputs plus valid qualification evidence. Presentation edits unrelated to simulation leave the key stable.

## Fire adapter, import and macOS delivery

Keep generic reader/writer/codec under src/Library/Simulation, with no fire fields or OpenVDB dependency. FireSequence remains the authority for legacy envelopes, physical records, labels, channel/domain constraints, render admission and provenance. Refactor validation so the adapter can process the original typed VDB grids and their sparse topology before any conversion to dense doubles. Use the existing prepared-frame transaction for both readers. Keep the exact existing successful legacy sidecar schema, sequence id, source-VDB digest and reason codes. Store native digests exclusively in the separately verified conversion receipt keyed by sequence id, source ordinal and source digest. Test the old successful sidecar golden round-trip and run the existing EXR/PNG verifiers on converted successful output. Unqualified producer, foreign import, unsupported optics, transport or output continues to limit fidelity regardless of a label in a cache.

Use a bundled VDB-capable import executable alongside the macOS app, with its privately bundled transitive libraries and notices. The GUI locates it through its bundle, passes explicit arguments, and chooses a writable per-user cache outside the source directory. Include the helper and its dependency closure in Xcode development products and Opto packaging, runpath rewriting, signing and verification. No Homebrew lookup at playback or implicit reliance on a make-built CLI. Native-only playback needs neither helper invocation nor VDB linkage. On a cold preview open, validate the envelope and metadata without opening unselected source payloads. Verify and convert only the requested ordinal on first use, including any initial frame genuinely needed to prepare a render. A legacy frame listed in the source but not yet converted is available for demand import; it is distinct from an unpublished solver frame. Full offline conversion is explicit. The CLI uses the same on-demand default and conversion logic on VDB-enabled builds. Keep original sealed scenes and source bundles read-only. A foreign sequence is always preview.

For each legacy import bind source envelope digest, validated sequence id, ordinal, actual source VDB SHA-256, converter version/format and resulting native SHA-256 into a conversion receipt. Use checked native payload digests for all cache reads. A self-consistent receipt copied from an untrusted location cannot establish fidelity. For a legacy predictive request, run the trusted local importer over the verified original preimages and compare its deterministic output/receipts against the proposed cache before admission. Preserve the current physical validation and all-frame preflight for predictive loads. An offline copied conversion can play as preview using a validated native manifest; inability to establish predictive evidence refuses predictive playback. Portable native production evidence is a separate admission path. M1 never upgrades existing fire evidence. Scene-relative paths are resolved against the input document; constrain all cache payload names to digest-derived local paths and reject traversal/symlink substitution.

## Acceptance and regression checks

- Differential against the shipped legacy reader for all available M0 frame components. Test sparse topology against the original VDB trees independently, including background, inactive nonbackground, active background, signed zero where legal, tiles and transforms. Hand-encoded cross-platform native input and golden writer bytes catch shared encoder/decoder layout errors.
- Differential time tests at nextafter on both sides of boundaries, last endpoint, nonzero first index, scaled time, nominal/open/close shutter and advection. Exercise 0/1 frames, interior holes, out-of-span policies, committed missing/corrupt data, rollback and predictive refusal. Instrument payload opens with a cold cache and a corrupt unselected source frame N: opening/rendering frame 0 never reads N, selecting N refuses transactionally, and predictive preflight refuses up front. Transplant a valid native payload and forge a consistent receipt; predictive admission must reject both.
- Competing publishers, stale expected parent, conflicting replay, crash after each publication boundary, stopped/resumed writer, last-complete visibility, old snapshots across rebake and shared live storage reuse. Reject huge sparse bounds or hostile lengths within the budget.
- On a relocated macOS app with empty conversion cache, read-only legacy inputs, and no build-tree or Homebrew lookup, open the unchanged legacy scene, import and render. Reopen native-only with the helper unavailable. Use a keyed fixture for time selection until M4. Exercise two deliberately different frames; check selected ordinal, source digest, prepared generation and region of interest. Compare the matching derived showcase input against the M0 paired render (raw and denoised) at the recorded settings. An empty or wrong-frame negative control must fail.
- Trace the canonical selected time through the shared controller, Job external rasterizer and prepare/freeze. Record interactive viewport behavior separately from GUI production output. Register new library files in all five project lists. Run focused, hygiene, fast-tier and build gates, then independently review implementation before acceptance.

## Independent design review, 2026-11-22

| Review axis | Confirmed failure scenario | Resolution after rereview |
|---|---|---|
| Publication and recovery | Lost writer updates, split seals, pinned snapshots referring to retired storage | Exclusive writer lock, epoch/parent validation, ordered durability and retained immutable bytes |
| Time and partial coverage | Holding the latest partial frame silently renders an unpublished ordinal | Map against authored support, then classify availability; test holes, endpoints and unavailable preview |
| Resource limits and portability | Sparse input expands beyond the process budget, or two readers interpret the same overlapping bytes differently | Bound total live allocations, reject overlap and verify an independently encoded binary fixture |
| Legacy admission and representation | A forged native receipt claims predictive fidelity or conversion drops inactive values | Recompute predictive mappings from verified source bytes, preserve VDB topology, compare prepared values separately |
| Provenance | Adding a native digest to an existing successful sidecar breaks the exact-key verifier | Keep native digest in a separate receipt and test legacy verification on output |
| GUI packaging and frame selection | A development app finds Homebrew, or a successful render always selects frame zero | Bundle and verify the importer; use relocated clean-install tests, two explicit frame selections and a negative control |
| Fresh review of cold preview | Opening an old scene eagerly hashes all VDBs before showing the first frame | Demand-import the requested frame; instrument actual file opens and compare preview and predictive refusal |

Three independent reviewers checked their revised areas. A fourth reviewer examined the full design afresh, identified the cold-preview issue, and confirmed its resolution. All four reported no outstanding P1/P2 design findings. Runtime behavior remains to be demonstrated during implementation.
